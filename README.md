# Mass Video Processor 1.0.4

Пакетная обработка MP4/MOV/WebM прямо в браузере (FFmpeg WASM). Видео не покидают устройство.
Все файлы лежат в корне (без папок), чтобы их можно было загрузить в GitHub с телефона за один раз.

## Как запустить с телефона (без компьютера)
1. **Распакуйте ZIP**: Files by Google → долгое нажатие на архив → «Извлечь».
2. **GitHub**: github.com в Chrome → войдите → «New repository» (например, `mass-video-processor`, Public) → Create.
3. На странице репозитория: **«uploading an existing file»**. «choose your files» → откройте распакованную папку → выделите **все** файлы (долгое нажатие → «Выбрать все») → Commit changes. Проверьте, что в репозитории есть все 20 файлов (`package.json`, `index.html`, `vite.config.ts` и остальные).
4. **Cloudflare Pages**: dash.cloudflare.com → Workers & Pages → Create → Pages → Connect to Git → ваш репозиторий.
   - Build command: `npm run build`
   - Build output directory: `dist`
   - Environment variable: `NODE_VERSION` = `20`

   Save and Deploy, через 1–3 минуты будет ссылка `https://<имя>.pages.dev`.
   **Netlify (альтернатива)**: Add new site → Import from Git → репозиторий (настройки возьмутся из `netlify.toml`).
5. Откройте ссылку в Chrome на Android. Меню ⋮ → «Добавить на главный экран».

## Как пользоваться
- Начните с 2–3 коротких роликов. Экран включён, телефон на зарядке (приложение просит блокировку засыпания).
- Первый запуск обработки скачивает ядро FFmpeg (~30 МБ) с jsDelivr (запасной источник: unpkg). Нужен интернет. Видео никуда не отправляются.
- Во время обработки удалять файлы из очереди нельзя; после завершения или отмены можно. Отмена останавливает текущий файл, остальные остаются в очереди, повторный запуск продолжит с них (файлы с ошибкой или отменённые обработаются заново).
- Готовые файлы хранятся в памяти. При суммарных 1 ГБ готовых результатов очередь остановится: скачайте файлы, удалите их из очереди и запустите снова.
- Скорость и соотношение сторон меняют результат (будет предупреждение). Соотношение меняется чёрными полями, без обрезки. «Масштаб кадра» больше 1 обрезает края, это суть эффекта.

## Добавлено в версии 1.0.4
- Выбор предельного размера кадра: исходный, 1080p, 720p, 480p.
- Нормализация громкости и настройка высоты тона с компенсацией длительности.
- Просмотр управления частью метаданных: удаление необязательных метаданных и установка поля title.
- Локальный поиск возможных дубликатов по отпечаткам (размер файла + выборки из начала, середины и конца), а также одинаковых профилей обработки.
- Новые параметры включены в сохранение настроек и профилей.

Ограничения: отпечатки выборок выявляют возможные совпадения, но не доказывают полное совпадение файлов. Перцептивное сравнение кадров пока не реализовано. Метаданные устройства не подменяются. Изменение метаданных и параметров кодирования не гарантирует оригинальность контента или попадание в рекомендации.

## Статус проверки (честно)
**Выполнено в среде разработки:**
- Реальный прогон всех цепочек фильтров на нативном ffmpeg (8 сценариев: все эффекты, соотношения 9:16 и 1:1, уменьшение, ускорение, нечётные размеры, WebM без звука): ошибок нет, звук сохраняется, длительность корректна.
- Проверка типов TypeScript с заглушками вместо `react`, `@ffmpeg/*`, `fflate`: ошибок нет. Это частичная проверка, не настоящий `npm run typecheck`.

**НЕ выполнено (в среде не было доступа к npm и интернету):**
- `npm install`, `npm run build`, `npm run typecheck`;
- загрузка WASM-ядра с CDN и работа FFmpeg WASM в браузере;
- запуск на Android и на Cloudflare Pages.

Если сборка на хостинге упадёт, откройте лог сборки, скопируйте текст ошибки и отправьте его разработчику.
